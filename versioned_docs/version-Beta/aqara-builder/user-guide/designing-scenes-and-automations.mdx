# Designing Scenes and Automations and Validating 3D Effects

Goal: Make devices respond as intended and distinguish simulation from real on-site feedback.


## Open Scene Builder

Use **More actions → Scene Builder** for the target plan. Check its name and the mode at the top right. Scenes and automations use the current space plan and devices.

| Type | Define |
| --- | --- |
| Scene | Device actions and intended target states |
| Automation | Trigger, required conditions and subsequent actions |

## Create Scenes and Automations with Agent

### Describe requirements

1. Open the correct plan and ensure device information is saved.
2. Specify room, trigger, conditions, actions and constraints; for example, turn on the entry light when activity is detected and ambient light is low.
3. Supply requested details and check device selection and capabilities.
4. Inspect the generated name, description and content in the list; reopen to check persistence.

### Adapt standard scenes

Existing implementation includes Cinema and Homecoming, selecting actions for this plan's rooms, devices and capabilities. Check returned presets and devices; inspect fallback behavior when curtains, media or dimming are unavailable. Production verification is still required.

## Lists, Workflow and References

### View and manage

Inspect names, descriptions and referenced devices. Open a target to check actions. Before deleting, check usage and current reference warnings.

### View Workflow

Inspect triggers, conditions, actions and connections. Use Workflow to understand and check the relationships between triggers, conditions and actions.

### Import and check device references

Import supported existing definitions through the available control. Check format, object names and referenced devices. Fix missing/deleted/invalid references before simulation or deployment; external device identities are not automatically the current household's devices.

## Simulation and 3D Preview

### Run automations and inspect states

**Check outcomes as well as playback status.** Starting execution or seeing “running” does not establish that every action completed.

1. Confirm **Simulation mode**.
2. Expand **Automations**, choose an automation and select **Play**.
3. Inspect execution, **Device States**, lighting, curtains and other supported effects.
4. For time-dependent rules, use available simulation-time controls and inspect unsupported actions, missing references and diagnostics.

## Real Device States and Debugging

1. Link and verify the on-site Studio, mappings and access rights.
2. Open **Studio Live** or the available live entry and confirm **Live mode**.
3. Expand device states and compare changes with the site.
4. With appropriate permission, control devices or run logic and check actual feedback.
5. If states do not update, check Studio connection, device connectivity, mappings and rule references.
