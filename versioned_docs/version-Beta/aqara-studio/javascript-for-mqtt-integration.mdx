# JavaScript Script for MQTT Integration

This document introduces how to use a JavaScript script in Aqara Studio to add device data points and their parsing methods.

## Script Overview

The script **must** include the following 4 JavaScript methods:
- [parseDiscoveryResponse](#parsediscoveryresponse)
- [parseDiscoverPointsResponse](#parsediscoverpointsresponse)
- [parseReportRequest](#parsereportrequest)
- [buildWriteRequest](#buildwriterequest)

:::tip
Do not modify the parameters or the input and output structures of these methods.
:::

## Console Logging

Scripts can output diagnostic logs through `console.log`, `console.info`, `console.debug`, `console.warn`, and `console.error`. Multiple arguments are joined with spaces, while `warn` and `error` messages use the `[warn]` and `[error]` prefixes. Logs appear in the read-only `Console Content` field on the protocol configuration page and are limited to 2048 characters; older content is replaced when the limit is exceeded. Each script parser accepts up to 20 log entries per second; excess entries are discarded and summarized in the next time window. Each entry retains up to 512 characters and converts only the first 16 arguments. Do not log unconditionally inside loops or high-frequency message handlers; use a debug condition or sampled logging instead.

## parseDiscoveryResponse

This method declares the MQTT devices to be added to Aqara Studio.

### Device Object Structure

| Field Name | Required | Description |
|-----------| --- |-------------|
| deviceName | Optional | Device name. An empty value is treated as an empty string. |
| deviceId | Required | Device ID. |
| brokerEndpoint | Required | MQTT Broker address. |
| brokerPort | Required | MQTT Broker port. The default port is `1883`. |
| connectionType | Required | Connection type. The default value is `3`. Supported values: <ul><li>0: Anonymous</li><li>1: SSL anonymous</li><li>2: SSL username/password</li><li>3: Username/password without SSL</li></ul> |
| username | Conditionally required | Username. Required depending on `connectionType`. |
| password | Conditionally required | Password. Required depending on `connectionType`. |

### Example

```javascript
function parseDiscoveryResponse() {
	return [
		{
			deviceName: "TestDevice",
			deviceId: "device-001",
			brokerEndpoint: "127.0.0.1",
			brokerPort: 1883,
			connectionType: 3,
			username: "admin",
			password: "public"
		}
	];
}
```
## parseDiscoverPointsResponse

This method declares to Aqara Studio "which data points this device supports". Aqara Studio passes `deviceId` as the first parameter when calling this function.

You need to return an array containing one or more data point objects (such as `pointId`, etc.; for more details, please refer to [Point Object Structure](#point-object-structure)). Aqara Studio will call this function during the discovery process of data points, parse the return value, and thus identify all data points supported by the device, enabling seamless integration and control of these points.

### Point Object Structure

| Field Name | Required | Description |
|-----------| --- |-------------|
| pointId   | Required | Data point ID. Please consult the device manufacturer to obtain the actual ID to allow Aqara Studio to discover this point. |
| pointName | Required | Name for the data point defined by you. |
| devType | Conditionally required | Corresponds to `deviceType` in the Aqara Data Model Specification. Fill it when defining a point based on Aqara Spec. For the specific available values, please refer to [Device Types](../aqara-developer/aqara-data-model-specification/device-types.mdx). |
| functionCode | Conditionally required | Corresponds to `functionCode` in the Aqara Data Model Specification. Fill it when defining a point based on Aqara Spec. For the specific available values, please refer to [Function Codes](../aqara-developer/aqara-data-model-specification/function-codes.mdx). |
| traitCode | Conditionally required | Corresponds to `traitCode` in the Aqara Data Model Specification. Fill it when defining a point based on Aqara Spec. For the specific available values, please refer to [Trait Codes](../aqara-developer/aqara-data-model-specification/trait-codes.mdx). |
| dataType  | Conditionally required | Required for general data points. Data point type. Supported values: <ul><li><code>bool</code>: Boolean</li><li><code>numerical</code>: Numeric</li><li><code>enum</code>: Enumeration</li><li><code>text</code>: Text</li></ul> |
| enumRange | Conditionally required | Enumeration options. Required only when a general data point uses `dataType: "enum"`. The array must not be empty. Each item contains an integer `value` and a string `label`; both must be unique, and `label` must not be empty. |
| trueText / falseText | Optional | Display text for a general Boolean data point. Effective only when `dataType` is `bool`. If omitted, `trueText` defaults to `开` and `falseText` defaults to `关`. Configure these fields only when custom labels such as `Enabled` / `Disabled` are needed. You can also use `activeText` / `onText` and `inactiveText` / `offText` as aliases. |
| min | Optional | Minimum value for a general numeric data point. Effective only when `dataType` is `numerical`; `minimum` can also be used as an alias. |
| max | Optional | Maximum value for a general numeric data point. Effective only when `dataType` is `numerical`; `maximum` can also be used as an alias. |
| step | Optional | Step value for a general numeric data point. It must be greater than 0. Effective only when `dataType` is `numerical`; `resolution` can also be used as an alias. |
| precision | Optional | Precision value for a general numeric data point. It must be greater than or equal to 0. Effective only when `dataType` is `numerical`. |
| decimals | Optional | Number of decimal places for a general numeric data point. It must be an integer greater than or equal to 0. Effective only when `dataType` is `numerical`. |
| unit / units | Optional | Unit for a general numeric data point. Effective only when `dataType` is `numerical`; use a registered unit name such as `kilowatt hour`, `watt`, `volt`, `ampere`, `celsius`, or `percent`. Studio displays the corresponding symbol, such as `kWh`, `W`, `V`, `A`, `°C`, or `%`. See [Unit Names and Symbols Supported by Scripts](./script-supported-unit-symbols.mdx) for the full mapping. The system can also match registered unit symbols. |
| access    | Conditionally required | Required for general data points. Access capability bit mask. <ul><li>1: Readable</li><li>2: Writable</li><li>3: Readable and writable</li></ul> |
| subTopic  | Conditionally required | (**Only applicable for MQTT devices**) Required for readable or reportable points. Aqara Studio subscribes to this topic to get the latest data for this point. Please fill in according to your device protocol or manufacturer documentation. When one point needs to receive multiple upstream message types, you can use MQTT wildcards such as `+` or `#`. |
| pubTopic  | Conditionally required | (**Only applicable for MQTT devices**) Required for writable points. Aqara Studio sends control message data to this topic for the data point. Please fill in according to your device protocol or manufacturer documentation. (For read-only points, leave this field empty) |

:::note
For `numerical` points, when Aqara Studio calls `buildWriteRequest`, it formats the write value by `decimals` first; if `decimals` is not configured, it infers decimal places from `step` / `resolution`. To avoid binary floating-point artifacts such as `0.30000030249357224`, explicitly configure `decimals` or `step` for points that write fractional values. `precision` only describes precision and is not used as the decimal-place truncation rule for outgoing write payloads.

If a numeric point is used by energy statistics or other unit-dependent features, configure `unit` or `units`. For example, use `kilowatt hour` (displayed as `kWh`) for accumulated energy, `watt` (`W`) for current power, `volt` (`V`) for voltage, `ampere` (`A`) for current, and `celsius` (`°C`) for temperature. Enter unit names exactly as shown in [Unit Names and Symbols Supported by Scripts](./script-supported-unit-symbols.mdx), including case and spaces.
:::

:::tip
When adding new data points, you may choose one of the following approaches depending on your needs:

- **Based on Aqara Spec**: You need to fill in fields such as `devType`, `functionCode`, and `traitCode`, which enables the data point to be compatible with the Aqara Spec.
- **General Approach**: You only need to fill in the basic fields such as `dataType` and `access`.
:::

			devType: "AirConditioner",
			functionCode: "Output",
			traitCode: "OnOff",
			subTopic: "/WEI-iEdge/realdata/xxx",
			pubTopic: "/WEI-iEdge/write/req/xxx"
		},
		// Add points by the general approach

			enumRange: [
				{ value: 0, label: "Off" },

			],

## parseReportRequest

This method extracts the current value of a specified data point (`pointId`) from the reported data sent by the device.

When Aqara Studio receives a message reported by the device, it will call this function and pass in the data point ID and the original message string. You need to implement logic in this function to extract the value corresponding to the specified `pointId` from the `values` field. In this way, Aqara Studio can update and display the value of the data point in real time.

:::tip
Please customize the parsing logic based on the actual data reporting protocol of your device to ensure you can accurately extract the numeric value corresponding to `pointId` from the original message (for example, `obj["values"][pointId]` in the example).
:::

### Example

```javascript
// The following example parses a JSON message string reported from an MQTT device
function parseReportRequest(pointId, jsonStr) {
	try {
		const obj = JSON.parse(jsonStr);
		return obj["values"][pointId]?.toString();
	} catch (e) {
		return null;
	}
}
```

## buildWriteRequest

This method constructs the command string to control the device based on the data point ID to control and the value to set.

When Aqara Studio needs to send a control command to a device (such as switch on or off the device, set temperature), it will call this function and pass in the device ID, target data point ID, and value to be set. The function must return a string that meets the control command format required by the device protocol, usually including device identifier, timestamp, and specific value fields.

Please construct the object structure within the function according to the actual acceptable message format of your device. For example, for an MQTT device, you may include fields like `node`, `group`, `timestamp`, and write the value corresponding to `pointId` in the `values` field.

### Example

```javascript
// Example: Control an MQTT device via a JSON string
// The value parameter is automatically passed in by Aqara Studio; no need to manually declare or assign it
function buildWriteRequest(deviceId, pointId, value) {
	try {
		const obj = {
			"node": "Chiller",
			"group": "1#Chiller",
			"timestamp": 1768204054654,
			"values": {

			},
			"errors": {

			},
			"metas": {

			}
		};
		obj.values[pointId] = parseFloat(value);
		return JSON.stringify(obj);
	} catch (e) {
		return null;
	}
}
```

## Complete Example

Below is a complete example for adding data points for an MQTT device:

The `globalThis` registrations in the example are dynamic: register only the functions you actually implement; functions that are not implemented do not need to be registered.

:::note
The example below only demonstrates a common MQTT integration flow: subscribe to one topic filter that receives multiple upstream message types, parse status/event/command-response messages by type, and correlate command responses with write requests by request ID. Replace the topic, field names, and enum values with the actual device protocol.
:::

```javascript
(function() {
	var DEVICE_ID = "device-001";
	var SUB_TOPIC = "/example/" + DEVICE_ID + "/+/json";
	var PUB_TOPIC = "/example/" + DEVICE_ID + "/cmd/json";
	var nextRequestIdValue = 1;
	var pendingWrites = {};

	function parseDiscoveryResponse() {
		return [
			{
				deviceName: "Example MQTT Device",
				deviceId: DEVICE_ID,
				brokerEndpoint: "127.0.0.1",
				brokerPort: 1883,
				connectionType: 3,
				username: "username",
				password: "password"
			}
		];
	}

	function parseDiscoverPointsResponse(deviceId) {
		return [
			{
				pointId: "switch.on",
				pointName: "Switch",
				dataType: "bool",
				access: 3,
				subTopic: SUB_TOPIC,
				pubTopic: PUB_TOPIC
			}
		];
	}

	function parseReportRequest(pointId, jsonStr) {
		try {
			var obj = JSON.parse(jsonStr);
			if (pointId !== "switch.on") {
				return null;
			}

			return parseStatusReport(obj)
				|| parseEventReport(obj)
				|| parseCommandResponse(obj);
		} catch (e) {
			return null;
		}
	}

	function parseStatusReport(obj) {
		if (obj.type !== "status") {
			return null;
		}
		return toBoolString(obj.values && obj.values["switch.on"]);
	}

	function parseEventReport(obj) {
		if (obj.type !== "event" || obj.pointId !== "switch.on") {
			return null;
		}
		return toBoolString(obj.value);
	}

	function parseCommandResponse(obj) {
		if (obj.type !== "response" || obj.requestId === undefined) {
			return null;
		}

		var key = String(obj.requestId);
		var pending = pendingWrites[key];
		delete pendingWrites[key];

		if (!pending || obj.success !== true) {
			return null;
		}
		return pending.value;
	}

	function buildWriteRequest(deviceId, pointId, value) {
		try {
			if (pointId !== "switch.on") {
				return null;
			}

			var writeValue = toBoolString(value);
			if (writeValue === null) {
				return null;
			}

			var requestId = nextRequestId();
			pendingWrites[String(requestId)] = {
				pointId: pointId,
				value: writeValue
			};

			var values = {};
			values[pointId] = writeValue === "1";

			return JSON.stringify({
				type: "command",
				requestId: requestId,
				values: values
			});
		} catch (e) {
			return null;
		}
	}

	function toBoolString(value) {
		if (value === true || value === 1) {
			return "1";
		}
		if (value === false || value === 0) {
			return "0";
		}

		var text = String(value).toLowerCase();
		if (text === "true" || text === "on" || text === "1") {
			return "1";
		}
		if (text === "false" || text === "off" || text === "0") {
			return "0";
		}
		return null;
	}

	function nextRequestId() {
		nextRequestIdValue += 1;
		return nextRequestIdValue;
	}

	globalThis.parseDiscoveryResponse = parseDiscoveryResponse;
	globalThis.parseDiscoverPointsResponse = parseDiscoverPointsResponse;
	globalThis.buildWriteRequest = buildWriteRequest;
	globalThis.parseReportRequest = parseReportRequest;
	return null;
})();
```
