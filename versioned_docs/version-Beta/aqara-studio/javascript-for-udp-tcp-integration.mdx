# JavaScript for UDP and TCP Integration

TCP/UDP use `describe`, `encode` and `decode` from the [unified contract](./unified-protocol-script.mdx). This reference covers byte messages, discovery settings, framing and message correlation.

## Byte messages {#messages}

Return `{bytes: Uint8Array or integer array, isResponseExpected?: Boolean}` from encode. Bytes are integers 0 to 255. Bare arrays, text and implicit HEX strings are not accepted.

`isResponseExpected` defaults to true. False is only for a vendor-defined one-way `write`; do not disable read/probe/discovery response checks to hide timeouts. Sending does not prove business execution.

Ordinary receive inputs contain `bytes` and the owning business `deviceId`, not pre-matched `operation`, `pointId` or `requestId`. Decode must recover classification/correlation from the protocol and return a [standard result](./unified-protocol-script.mdx#results). An ID alone is insufficient even when ID matching is enabled.

Reports follow complete frame → decode(report) → point application → encode(ack). Return null when no ACK is needed. ACK transmission occurs outside the JS execution thread and does not wait for another response. Validate CRC, escaping, sequences and vendor error codes according to the actual protocol.

## Discovery configuration {#discovery}

Use `describe().discovery`:

| Field | Rule |
| --- | --- |
| `discoveryType` | `"udp"` or `"tcp"`; defaults to the owning plugin's transport |
| `ip` | IPv4 literal, unicast/broadcast/multicast; required for TCP, optional/blank for UDP |
| `port` | Required integer 1 to 65535; request destination port |
| `editable` | Default false; true allows the page to override script defaults |

```json title="Example describe().discovery"
{"discoveryType":"udp","port":5919,"editable":false}
```

Omitting discovery retains manual configuration. An invalid declared configuration or execution failure fails discovery rather than silently falling back.

With UDP and no IP, Studio derives broadcast destinations from eligible up, non-loopback, non-virtual, non-point-to-point, non-link-local IPv4 interfaces, sorts/deduplicates them and sends to all. No eligible address is an explicit failure. The page displays the first sorted address. An explicit IP remains authoritative rather than being replaced by automatic broadcasts; editable=true uses the user's confirmed configuration.

A TCP plugin may discover over UDP. Its encode input still contains `transport:"tcp"`, plus operation discoverDevices, ip, port and config. A fixed response listener may be specified on the **encoded discovery message**, not on devices:

```json title="TCP-plugin UDP send/listen example (not a vendor protocol)"
{"bytes":[170,1,85],"responseIp":"0.0.0.0","responsePort":9001}
```

responseIp requires a valid responsePort. Use the actual response multicast group when required. The send destination port is not the local listening port. Multiple broadcast targets must return consistent responseIp/responsePort.

These listener overrides belong to the **TCP plugin's UDP discovery** only. The UDP plugin's own discovery opens an ephemeral local DatagramSocket and reuses it to receive replies; it does not read responseIp/responsePort or join a response multicast group. A vendor requiring a fixed UDP reply port/group needs an appropriate implemented discovery path or transport extension, not extra ignored JS fields.

Decode discovery as `{devices:[{deviceId,deviceName,ip,port,...}]}`. IP/port are subsequent device communication targets; optional fields include vendor, model and firmwareVersion; UDP can also supply localPort. Obtain vendor serial numbers from discovery replies instead of hardcoding site values from an example.

Discovery decode receives response bytes, not the packet sender's IP/port or the earlier destination fields. Derive device endpoints from documented payload fields or authorized known configuration. If only the UDP source address identifies the endpoint, the current callback cannot recover it; report that capability gap rather than using message.ip/message.port or a broadcast/group address as the device endpoint.

Device discovery requires a real supported transport procedure; encode(null) does not automatically import static TCP/UDP devices. Static **point** discovery is supported: encode(discoverPoints) returns null and decode receives bytes=null to return pointDefinitions.

## Framing and reassembly {#framing}

UDP preserves datagram boundaries. TCP is a stream: one socket read is not necessarily one frame.

| describe().framing field | Rule |
| --- | --- |
| `frameStartBytes` | Required nonempty byte array |
| `lengthKnownAfterBytes` | Required integer, at least header length and at most maxMessageBytes |
| `remainingBytes` | Optional nonnegative integer, default 0 |
| `totalLength` | Optional fixed total length, at least lengthKnownAfterBytes |

With totalLength, framing is fixed length. Otherwise the **lengthKnownAfterBytes-th byte (1-based)** is an unsigned length, with 0 meaning 256. Total length is lengthKnownAfterBytes + data length + remainingBytes, bounded by Parser maxMessageBytes.

This is not an arbitrary length-expression parser. There are no delimiter, lengthFieldSize or custom multibyte-length fields. Without framing, TCP retains chunk-based fallback. Special JSON/delimiter protocols need bounded script reassembly, isolated by deviceId with size/count/lifetime limits. Never share one pending buffer across devices. Some multistage protocols still require transport extensions.

TCP fallback reads at most **128 bytes per chunk**, not one complete message or a guaranteed 128 bytes. UDP without framing passes the whole bounded datagram. With framing enabled, UDP extracts only the **first complete frame** inside that datagram, does not retain the tail and does not reassemble across datagrams. Do not enable this framing for vendor multi-frame datagrams without accounting for that limit.

## Five-byte demonstration protocol {#example}

This is a **fictional protocol**, not vendor device code. Assume an existing device with business ID demo-1 and frames `[0xAA, opcode, unit 1, value/error, 0x55]`. Read uses 0x10/0x90, write 0x11/0x91, probe 0x12/0x92, report 0x93. Volume ranges from 0 to 100.

The example supports static point discovery, read/write, probe and report, **not device discovery**. Configure an existing device through its published fields. Implement real discovery from the vendor document before enabling it.

```javascript title="Complete three-entry five-byte example"
(function () {
    "use strict";
    function describe() {
        return {
            contractVersion: 1, scriptVersion: "V1.0",
            protocol: {msgIdMatch: false, stateSyncMode: "query"},
            framing: {frameStartBytes: [170], lengthKnownAfterBytes: 1, totalLength: 5}
        };
    }
    function encode(r) {
        if (r.deviceId !== "demo-1") return null;
        if (r.operation === "probe") return {bytes: [170, 18, 1, 0, 85]};
        if (r.pointId !== "volume") return null;
        if (r.operation === "read") return {bytes: [170, 16, 1, 0, 85]};
        if (r.operation !== "write") return null;
        if (typeof r.value !== "number" || !isFinite(r.value) ||
                Math.floor(r.value) !== r.value || r.value < 0 || r.value > 100) {
            throw new Error("Invalid volume");
        }
        return {bytes: [170, 17, 1, r.value, 85]};
    }
    function decode(m) {
        if (m.operation === "discoverPoints") {
            return {pointDefinitions: m.deviceId === "demo-1" ? [
                {pointId: "volume", pointName: "Volume", dataType: "number",
                 access: 7, min: 0, max: 100, step: 1, decimals: 0}
            ] : []};
        }
        var b = m.bytes;
        if (m.deviceId !== "demo-1" || !b || b.length !== 5 ||
                b[0] !== 170 || b[2] !== 1 || b[4] !== 85) return {operation: "ignore"};
        if ((b[1] === 144 || b[1] === 147) && b[3] <= 100) {
            return {operation: b[1] === 144 ? "read" : "report", deviceId: m.deviceId,
                    points: [{pointId: "volume", value: b[3]}]};
        }
        if (b[1] === 145 || b[1] === 146) {
            return {operation: b[1] === 145 ? "write" : "probe", deviceId: m.deviceId, code: b[3]};
        }
        return {operation: "ignore"};
    }
    globalThis.describe = describe;
    globalThis.encode = encode;
    globalThis.decode = decode;
})();
```

Without IDs, serialized framework transactions still cannot completely distinguish late responses of the same type. Use stable protocol IDs when available; the latest sent request is not reliable correlation.

## Debugging checklist {#debugging}

Use Open [connectionSnapshot](./protocol-script-mcp-api.mdx) for observed bound/remote endpoints and discovery interfaces. It does not scan, send or reconnect. CONNECTED still requires real probe/read evidence.

Check discovery destination versus listener port, subnet/interface, changed IP, framing, IDs, types and actual point application. Do not change the user's gateway, VPN or firewall for testing. Windows multihomed verification is not M300 verification.

Configure polling through Network/Proxy settings. Distinguish send, ACK and observed state in Agent tests. Stop debug sessions afterwards without closing shared business connections.
