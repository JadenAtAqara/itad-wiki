# 创建 App 看板与应用界面

本篇目标：为客户制作可查看和操作的界面，核对预览后交给相应成员使用。


## 创建项目 App 看板

1. 在项目打开 **App Dashboard**。
2. 空列表选择 **Start from Scratch**，填写名称并创建。
3. 打开目标看板；首次可能显示 **No Dashboard Available**，继续用 Agent 生成内容。
4. 已有看板可在列表搜索、打开，并按卡片操作管理名称或删除。

## 生成、修改与预览

### 说明界面要求

向 Agent 写明房间、设备、场景、控件和风格，例如“显示客厅和玄关，提供灯光开关与回家场景按钮”。等待生成后检查右侧手机预览。

### 逐项核对实际界面

| 检查项 | 要检查什么 |
| --- | --- |
| 名称与房间 | 是否符合当前项目 |
| 控件与场景 | 是否包含所需按钮、状态和操作 |
| 模拟 / 真实数据 | 是否标记 Simulated；是否连接真实数据 |
| 布局与文案 | 手机尺寸下是否可读、可操作 |

*实测 Agent 回复与实际预览曾有内容偏差，应以预览为准。*

### 对话修改与下载

**下载后找不到文件：**先看浏览器的下载列表，确认文件确实完成；核对看板名和文件时间，再打开检查内容。界面预览成功与产物下载成功分别确认。

保持目标看板详情打开，说明具体区域和改动，检查修改后的实际内容。

## 独立应用创作与可视化编辑

独立应用编辑工作台与项目 App Dashboard 是不同入口。使用已开放的独立工作台时，按以下流程处理：

### 应用、多页面与素材

创建或打开应用，选择页面；添加页面和需要的资源，配置页面间跳转。预览时逐页检查，保存后重新打开核对。

### 可视化编辑与数据点绑定

在页面编辑器选中元素，修改布局、样式和素材。对需要展示状态或控制设备的组件，选择目标 Studio 数据点，设置可用的显示与动作绑定；通过实时订阅检查状态更新，控制动作需现场验证。

### 应用与页面复用

通过当前工作台开放的市场入口预览、获取或复用应用 / 页面资源。复用后重新检查数据绑定、图片资源、跳转和目标设备。

旧版 Application UI 的菜单位置不直接套用到项目看板。

## 部署给 Studio 成员

1. 确认目标成员已加入目标 Studio。
2. 在看板或 Studio 资源页使用 **Deploy App dashboard** 等当前部署入口。
3. 选择 Studio 和成员，核对界面与接收对象后提交。
4. 查看分配结果，并让目标成员实际打开确认。
5. 分配错误时，在 Studio 已部署资源的成员界面管理中更换或取消分配，见[管理 Studio、项目成员与已部署资源](managing-studio-and-members.mdx)。

界面部署面向成员；空间方案部署需要方案设备与现场设备匹配。两类资源分别核对部署结果。
