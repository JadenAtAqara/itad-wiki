# 设计场景与自动化，验证三维效果

本篇目标：让设备按约定方式联动，并区分模拟效果和现场真实反馈。


## 进入场景编辑

从目标方案 **More actions → Scene Builder** 进入，检查方案名与右上角模式。场景和自动化围绕当前空间方案及设备工作。

| 内容 | 应明确什么 |
| --- | --- |
| 场景 Scene | 执行哪些设备动作，产生什么目标状态 |
| 自动化 Automation | 什么触发、满足什么条件、随后执行哪些动作 |

## 用 Agent 创建场景与自动化

### 描述需求

1. 打开正确方案并确认设备信息已保存。
2. 描述房间、触发、条件、动作及限制。例如：“玄关传感器检测到活动且环境较暗时，打开玄关灯。”
3. 按 Agent 要求补充信息，检查所用设备及能力。
4. 生成完成后检查列表中的名称、说明与实际内容，重新打开核对是否已保存。

### 标准场景适配

现有标准场景实现包含“观影”和“回家”：根据本方案的房间、设备及能力选择动作。使用时先核对实际返回的可用预设和设备，缺少窗帘、媒体或调光能力时检查降级说明。

## 查看列表、Workflow 与引用

### 查看与管理

在场景 / 自动化列表查看名称、说明和设备引用。打开目标内容核对动作；删除前确认它是否仍被使用，并检查当前页面的引用提示。

### 查看 Workflow

打开对应自动化的 Workflow，检查触发、条件、动作和连接关系。Workflow 用于理解和核对触发、条件及动作之间的逻辑关系。

### 导入与设备引用检查

使用当前开放的导入入口加载已有定义，核对格式、对象名称和引用设备。缺失、删除或失效的设备要先修正，再进行仿真和部署；不把外部方案的设备身份直接当作当前家庭设备。

## 仿真与三维预览

### 运行自动化并查看状态

**看状态，也看结果。**点 Play 后先观察是否进入执行，再检查设备状态及效果变化；仅看到播放按钮变化或“执行中”，还不能确认所有动作已完成。

1. 确认右上角为 **Simulation mode**。
2. 展开 **Automations**，选择目标自动化，点 **Play**。
3. 查看动作过程、**Device States** 及灯光、窗帘等支持的效果。
4. 对有时间条件的规则，按当前提供的模拟时间控件测试；查看不支持动作、缺失引用与执行诊断。

### 简模、精模与视角

| 控件或模式 | 用途 |
| --- | --- |
| 2D / 3D | 在平面与立体视图核对同一布局 |
| Simple 3D | 用简模快速查看空间、点位和场景 |
| Detailed 3D | 在资源可用时查看更细致的家具和材质 |
| Top view / Overview / Free roam | 俯视、总览或进入空间漫游 |
| 楼层、剖切与展示环境 | 检查不同楼层、遮挡与可用光照环境 |

## 查看真实设备状态与调试

1. 关联并核对现场 Studio，确认设备映射和访问权限。
2. 进入 **Studio Live** 或当前实时入口，检查显示为 **Live mode**。
3. 展开设备状态，查看变化是否与现场对应。
4. 在有权限的情况下控制设备或执行联动，结合实际反馈判断是否成功。
5. 状态不更新时，依次检查 Studio 连接、设备在线、点位映射和规则引用。
