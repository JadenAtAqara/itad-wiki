# 关联 Studio，匹配设备并完成现场部署

本篇目标：把保存的空间和自动化对应到现场设备，并确认实际应用结果。


## 连接目标 Studio

### 云端连接

1. 打开已保存的方案，点 **Link Studio**；也可从 **Device Matching** 空态关联。
2. 在 **Connect Studio** 选择 **Cloud connection**。
3. 核对账号、地区、项目和 Studio。
4. 连接后确认设备列表、型号及可用能力已加载。

### 本地连接

选择 **Local connection**，按页面要求填写地址与连接凭据。先完成 Studio 初始化，让电脑与 Studio 处于可访问的局域网，连接后再次核对实际目标。

<img src="https://itad-aqara-docs-1300889962.aqara.com/dev/img/aqara-builder/zh/14-studio-selector.png" alt="云端与本地连接入口" style={{ width: '70%' }} />

*测试项目曾显示 No Studio is available in this project；应先检查项目、地区和权限。*

### 读取已有空间

使用当前开放的 Studio 空间读取入口导入已有户型或空间数据，检查房间、点位和方案内容，确认后保存。不要仅凭 Studio 连接成功判断空间已同步。

## 核对方案点位与实际设备

### 检查自动匹配

查看方案点位对应的 Studio 设备，逐项核对名称、型号、房间和实物。已有映射或匹配规则可能提供初始结果，仍须现场确认。

### 手动匹配、解除和设备识别

**不要按列表顺序猜设备。**名称相近或房间内有多台同型号设备时，先通过识别反馈与现场人员对应实物，再确认匹配。选完一项后回看方案点位与真实设备的两侧名称。

1. 找到未匹配或错配点位，选择正确的真实设备。
2. 调整前解除错误对应，检查是否重复使用同一真实设备。
3. 对支持识别的设备使用识别反馈，配合现场人员确认实物。
4. 更换 Studio 后重新检查映射和能力。

<img src="https://itad-aqara-docs-1300889962.aqara.com/dev/img/aqara-builder/zh/13-device-matching.png" alt="设备匹配页" style={{ width: '70%' }} />

*测试站验证到先关联 Studio 的提示；自动 / 手动匹配和实物识别待真机验证。设备匹配后仍需检查功能能力，不能仅凭“已匹配”判断兼容。*

## 检查、下发与失败处理

### 部署前检查

| 检查项 | 合格条件 |
| --- | --- |
| 方案与目标 | 当前保存版本及 Studio 均正确 |
| 空间数据 | 房间、点位与图谱可用于本次部署 |
| 设备引用 | 必要设备引用有效，匹配关系正确 |
| 设备能力 | 支持方案要求的动作 |
| 连接与权限 | Studio 可访问，当前账号可执行部署 |

### 下发空间与自动化

进入 **Deploy**，核对页面提供的导入方式、范围及影响后提交；观察各步骤进度、结果与回执。完成后查看 Studio 资源和历史，并在现场逐项测试关键设备与联动。

### 修正失败并重试

保留失败步骤和提示，检查连接、权限、缺失引用和匹配状态。修正后按当前重试入口操作，核对哪些步骤已完成、哪些需要重新执行，最终以资源结果与实际运行反馈确认。

## 现场常见问题

| 问题 | 先检查什么 |
| --- | --- |
| 找不到云端 Studio | 账号、地区、所属项目与访问权限 |
| 找不到本地 Studio | 初始化、地址、局域网可达性和凭据 |
| 不能继续部署 | Studio 关联、空间数据、设备引用及匹配状态 |
| 设备匹配了但动作不正确 | 型号能力、端点、控制关系和实际实物 |
| 部署成功但体验不符 | 实际配置与关键场景逐项验证结果 |
